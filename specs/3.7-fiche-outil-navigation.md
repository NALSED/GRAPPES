# 3.7 — Les onglets de modification des outils ne sont pas intuitifs

Répond au point **3.7** du pavé.

## Constat vérifié dans le code

Il n'y a **pas de vrais onglets** aujourd'hui. `ficheOutil(id)` dans `reglages.js`
construit, dans une seule fonction `dessiner()`, un panneau unique qui s'enchaîne du
haut en bas : nom, « comment il travaille » (nature), modèle, réglages du modèle,
champs `fait`/`recoit`/`renvoie`/`code`/`entree`/`sortie`/`cle`, rôle, effet, test —
sans aucun composant de bascule entre sections. Ce que Sednal appelle « onglets »
n'existe pas : c'est un seul panneau à faire défiler, avec des titres de groupe
(« puces ») mais rien pour sauter d'un groupe à l'autre ni pour savoir où on se
trouve dans le panneau.

Par ailleurs, l'ordre actuel des groupes n'est pas celui dans lequel on pense une
fiche d'outil : la description (« ce qu'il fait ») est coincée entre le modèle et
`recoit`/`renvoie`, la clé d'API est tout en bas, détachée des autres informations
d'identité, et rôle/effet sont séparés du test.

## Décidé avec Sednal : regrouper, pas onglets cliquables

Trois blocs, affichés les uns sous les autres avec des titres nettement plus
marqués (pas de contenu caché, pas de clic pour changer de section — on garde un
seul panneau continu, juste mieux organisé et plus facile à lire d'un coup d'œil) :

1. **Général** — nom, modèle (T1), description (« ce qu'il fait », T2)
2. **Réglages** — réglages propres au modèle choisi, rôle, effet (1.1)
3. **Vérifier** — test, clé d'API si l'outil en a besoin (T4)

Les champs `recoit`/`renvoie`/`code`/`entree`/`sortie` suivent le groupe auquel ils
appartiennent déjà par le sens (identité de l'outil → Général ; comportement →
Réglages), à préciser outil par outil au moment où momo implémente — pas de liste
figée ici, le principe des 3 blocs suffit.

## Ce que momo change

* `reglages.js`, `ficheOutil(id)` / `dessiner()` : réorganiser l'ordre d'affichage
  des groupes existants selon les 3 blocs ci-dessus ; titres de bloc plus visibles
  (taille/poids, séparation claire) que les titres de puce actuels — pas de nouveau
  composant d'onglets, pas de JS de bascule à écrire.
* Aucun champ n'est supprimé, renommé ou cassé par ce point — seul l'agencement
  visuel change. Les renommages/clarifications de champs décidés par ailleurs (T1,
  T2, T4, 1.1, 3.8.0X) s'appliquent indépendamment, dans leur bloc respectif une
  fois faits.

## Comment momo vérifie

* Ouvrir la fiche d'un outil quelconque : les 3 titres de bloc (Général / Réglages
  / Vérifier) apparaissent dans cet ordre, nettement plus visibles que le reste du
  texte.
* Aucun champ existant n'a disparu ni changé de comportement — seul l'ordre/la
  présentation a changé.
* La fiche reste un seul panneau défilant : aucun clic n'est nécessaire pour voir
  un champ qui était visible avant ce changement.
