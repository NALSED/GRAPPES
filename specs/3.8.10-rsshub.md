# 3.8.10 — RSSHub

Répond au point **3.8**, outil 10, dernière tuile du pavé. Rappel transverse : Modèle (T1),
Ce qu'il fait → Description (T2), Rôle/Effet (spec 1.1), Clé d'API (T4, pas pertinente — instance
auto-hébergée, pas de service tiers payant).

## Ce que fait RSSHub (explication, Sednal ne connaissait pas l'outil)

Beaucoup de sites web n'ont pas de flux RSS — pas de moyen automatique de suivre leurs nouveautés.
**RSSHub** est un projet libre déjà existant (pas à réinventer, `ne rien réinventer` respecté) qui
sait fabriquer un flux RSS pour un très grand nombre de sites qui n'en ont pas nativement. La tuile
demande à une instance RSSHub de transformer l'adresse d'un site en flux RSS ; grappes suit ensuite
ce flux avec le mécanisme déjà existant (`flux_rss.py`), sans rien à réinventer là non plus.

## Hébergement : auto-hébergé

Décidé avec Sednal : une instance RSSHub auto-hébergée (conteneur Docker), cohérente avec le reste
de son infrastructure (Bareos, Vault…), plutôt qu'une dépendance à un service public hors de son
contrôle.

## Comment la tuile se branche

1. L'instance RSSHub auto-hébergée est déclarée une fois, dans la configuration (`pilote.yaml`,
   sur le même principe que `suite.traduction_url` pour Traduction) — une adresse, pas de clé.
2. La tuile reçoit l'adresse d'un site (option « Site à transformer »), interroge RSSHub (qui
   choisit la bonne « route » pour ce site parmi celles qu'il connaît), reçoit en retour l'adresse
   d'un flux RSS.
3. Ce flux est ensuite traité **exactement comme un flux RSS ajouté à la main** dans
   `flux_rss.py` — lu une fois pour vérifier qu'il rend des articles, puis suivi comme n'importe
   quelle autre prise de grappes.
4. « Rafraîchir toutes les » (déjà présent, 30 minutes par défaut) reste : RSSHub reconstruit le
   flux à la demande, inutile de le réinterroger à chaque appel de grappes.

Si RSSHub ne connaît pas de route pour le site donné (certains sites ne sont pas couverts), la
tuile le dit clairement plutôt que d'échouer en silence — c'est une limite connue de RSSHub
lui-même, pas un bug de grappes.

## Ce que momo change

* Déployer une instance RSSHub auto-hébergée (image Docker officielle du projet).
* `config.py`/`pilote.yaml` : nouvelle entrée `suite.rsshub_url`, sur le modèle de
  `suite_traduction_url`.
* Nouveau module `suite_rsshub.py`, qui appelle l'instance et récupère l'adresse du flux produit
  pour un site donné.
* Câblage dans `pilote/pont/executer.py` (même zone que traduction/chemins/IA) : le flux obtenu
  rejoint le mécanisme `flux_rss.py` existant pour cette recherche.
* `suite_graine.py`, `_OUTILS`, tuile `rsshub` : `NON_APPLIQUES["rsshub"]` disparaît une fois
  câblé.
* `reglages.js` : pas de nouveau champ complexe, les deux options actuelles suffisent une fois le
  mécanisme réel branché.

## Comment momo vérifie

* Un site connu de RSSHub, sans flux natif : la tuile produit un flux, grappes y trouve des
  articles.
* Un site que RSSHub ne couvre pas : message clair, pas d'échec silencieux.
* Sans `suite.rsshub_url` réglée : la tuile refuse de s'appliquer et le dit (comme Traduction sans
  `traduction_url`).
