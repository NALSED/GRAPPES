# 3.4 — Élargir le panneau en tirant son bord gauche

Répond au point **3.4** du pavé de Sednal du 02/11/2026.

## Ce qui change

Le panneau latéral (`.panneau`, `static/suite/css/suite.css` ligne 143 : 480 px pour une source,
520 px avec `.large` pour un outil) reçoit une **poignée sur son bord gauche**. On l'attrape à la
souris et on tire vers la gauche pour l'agrandir.

Décidé par Sednal le 02/11/2026 :

* **Pas de largeur maximale** : le panneau peut aller jusqu'à prendre tout l'écran.
* **Jamais mémorisé** : chaque ouverture repart à la largeur de base (480 px source, 520 px outil),
  même si on l'a agrandi juste avant. Rien à écrire dans le navigateur pour ce point.
* **Largeur minimale** : celle d'aujourd'hui (480 px ou 520 px selon le panneau) — on ne tire jamais
  en dessous.

## Comment momo l'implémente

### La poignée

Une bande fine (6 à 8 px) collée au bord gauche du panneau, curseur `col-resize` au survol. Ajout
dans `ui.js`, dans la fonction qui construit le panneau (celle que tous les `ficheSource`,
`ficheOutil` etc. appellent — chercher `class: "panneau"` dans `ui.js`) :

````js
h("div", { class: "panneau-poignee", onpointerdown: (e) => demarrerRedimension(e, panneauEl) })
````

### Le redimensionnement

Capturer le pointeur (`setPointerCapture`), suivre `pointermove`, calculer la nouvelle largeur
depuis la position X de la souris jusqu'au bord droit de l'écran (le panneau est collé à droite,
`right: 0`), et l'écrire directement en style inline sur l'élément (`panneauEl.style.width =
\`${largeur}px\``) — pas de classe CSS à faire varier, une seule valeur qui change.

````js
function demarrerRedimension(e, panneauEl) {
  const largeurMin = panneauEl.classList.contains("large") ? 520 : 480;
  e.target.setPointerCapture(e.pointerId);
  const bouger = (ev) => {
    const largeur = Math.max(largeurMin, window.innerWidth - ev.clientX);
    panneauEl.style.width = `${largeur}px`;
  };
  const relacher = () => { window.removeEventListener("pointermove", bouger); window.removeEventListener("pointerup", relacher); };
  window.addEventListener("pointermove", bouger);
  window.addEventListener("pointerup", relacher, { once: true });
}
```` 

`Math.max(largeurMin, …)` tient la borne basse ; comme il n'y a pas de borne haute, pas de
`Math.min`.

### À l'ouverture et à la fermeture

* **Rien à lire au montage** : le panneau s'ouvre toujours à sa largeur de base (`width` fixé dans
  le CSS, pas de style inline posé à l'avance). C'est ce qui donne gratuitement le « jamais
  mémorisé » : on ne pose de style inline qu'au moment où l'utilisateur tire, jamais avant.
* **Rien à nettoyer à la fermeture** : le panneau entier (DOM compris) disparaît à la fermeture
  (`ficheSource`/`ficheOutil` referment en retirant le panneau), donc le style inline posé pendant
  le glissement part avec lui.

### CSS

````css
.panneau-poignee { position: absolute; top: 0; bottom: 0; left: -4px; width: 8px; cursor: col-resize; }
````

Rien d'autre à ajouter aux jetons : pas de nouvelle couleur, pas de nouvelle taille déclarée dans la
charte — la poignée est invisible (zone de prise, pas un trait dessiné). Si Sednal veut un repère
visuel au survol (un trait `accent` fin qui apparaît), c'est un ajout mineur à faire à ce moment-là,
pas une obligation de ce point.

## Comment momo vérifie

* Modifier une source, puis une recherche sauvegardée pour vérifier aussi un outil : le panneau
  s'ouvre à sa largeur habituelle (480/520 px).
* Tirer la poignée vers la gauche agrandit le panneau sans borne haute (jusqu'au bord gauche de
  l'écran).
* Tirer vers la droite ne descend jamais sous la largeur de base.
* Fermer puis rouvrir un panneau élargi : il revient à sa largeur de base.
* `test_aucune_valeur_de_style_en_dur` : relu, il ne contrôle que `font-size`/`border-radius`/
  `box-shadow`/`letter-spacing`/`padding`/`margin`/`gap` et les styles en ligne JS de la même liste.
  `width` et `left` n'y figurent pas — la poignée (CSS) et `panneauEl.style.width` (JS) passent sans
  y toucher.
