# 3.8.09 — Assistant IA

Répond au point **3.8**, outil 9. Rappel transverse : Modèle (T1), Ce qu'il fait → Description (T2),
Rôle/Effet (spec 1.1). Clé d'API (T4) ne s'applique pas ici : pas de clé, un agent déjà connecté
(voir plus bas).

## Fait vérifié : pas d'abonnement Pro/Max pour l'API, mais pour l'agent Claude Code oui

Vérifié auprès de la documentation officielle : un abonnement Claude Pro/Max ne donne **pas**
accès à l'API classique — séparée, avec sa propre facturation. Mais l'agent Claude Code (le même
programme que celui déjà installé sur .250 pour momo — `/areas/agent-ia.md`) se connecte, lui, avec
un abonnement Pro/Max, et peut être appelé en silence depuis un script, sans interface
(`claude -p "..."`), déjà fait aujourd'hui pour momo. **C'est ce mécanisme qui est retenu**, pas une
clé d'API : installer ce même agent sur .115, connecté une fois avec l'abonnement de Sednal, appelé
par grappes en coulisses pour chaque opération IA. Pas de facturation séparée, l'abonnement suffit.

## 1. Opération : liste fermée, mais extensible et cherchable

Comme pour Format de sortie (3.8.01), une liste fermée qu'on peut faire grandir sans casser l'
existant plutôt qu'une liste figée en dur :

* **Résumer** (actuel)
* **Classer / catégoriser**
* **Extraire des mots-clés**

Présentées en menu déroulant **avec une recherche** (utile dès que la liste dépasse une poignée
d'entrées, contrairement à Traduction où 19 langues tenaient dans une liste simple). Une nouvelle
opération s'ajoute comme un format s'ajoute (3.8.01) : un petit module qui se déclare, découvert
automatiquement, pas une liste à modifier à la main dans l'interface.

Toutes respectent la règle de l'outil : **aucun fait nouveau ajouté**, seulement un champ marqué
IA à côté des résultats (résumé, catégorie ou mots-clés) — jamais une correction ou un ajout à un
champ existant (nom, ville, etc.), qui resterait tel que trouvé.

## 2. Modèle : Claude, via l'agent déjà installé, pas une clé

Un seul fournisseur pour l'instant (décidé avec Sednal — ChatGPT/Gemini/local pourront s'ajouter
plus tard sur le même principe, pas construits maintenant). Réglages :

* **Modèle** : menu fermé des modèles Claude que l'agent installé sait utiliser (`claude --model`),
  pas en dur — demandé à l'agent, pas recopié à la main, pour suivre les nouveaux modèles sans
  mise à jour du code.
* **Effort** : menu fermé, seulement si l'agent installé sur .115 expose un réglage d'effort de
  raisonnement en ligne de commande — à confirmer par momo en l'installant ; sinon ce champ
  disparaît pour l'instant plutôt que de promettre un réglage qui n'existe pas.

## 3. Marquer les résultats : reste un choix, oui/non

Confirmé avec Sednal : ça reste activable/désactivable, pas forcé. Par défaut activé (cohérent avec
la fiabilité du programme), mais désactivable si besoin.

## Ce que momo change

* Installer l'agent Claude Code sur .115, connecté une fois avec l'abonnement Pro/Max de Sednal —
  même mise en place que `/areas/agent-ia.md` sur .250, adaptée à .115 (pas de Claude-Code-Router/
  OpenRouter ici, l'abonnement suffit).
* Nouveau module `suite_ia.py`, sur le modèle de `suite_traduction.py`, mais qui appelle l'agent en
  silence (`claude -p "..." --model <modèle>`, sortie lue et interprétée) au lieu d'un appel API
  direct. Lève une erreur claire si l'agent ne répond pas ou produit une sortie inexploitable —
  jamais un fait inventé en silence.
* Un petit registre d'opérations, comme `pilote/formats/` (3.8.01) : un module par opération
  (chacun fabrique le prompt envoyé à l'agent pour cette opération), découverte automatique,
  extensible sans toucher au cœur.
* Câblage dans `pilote/pont/executer.py`, au même endroit que `suite_plan.appliquer()` et la
  traduction (après les chemins, avant la vérification) : applique l'opération choisie aux
  résultats qui atteignent cette tuile, marque le champ ajouté si l'option est activée.
* `suite_graine.py`, `_OUTILS`, tuile `ia` : `cle_requise: false` (pas de clé, l'agent est déjà
  connecté) ; réglages Opération/Modèle (et Effort si disponible) en menus fermés dynamiques ;
  `NON_APPLIQUES["ia"]` disparaît une fois câblé.
* `reglages.js`, fiche Assistant IA : pas de champ clé ; les menus fermés ; interrupteur Marquer
  les résultats.
* `charte/nommage.md` : ajouter les noms des opérations si besoin.

## Comment momo vérifie

* Agent non installé ou non connecté sur .115 : la tuile refuse de s'appliquer, le dit clairement
  (comme Traduction sans `traduction_url`).
* Opération « Extraire des mots-clés » sur 3 résultats : chacun reçoit un champ mots-clés marqué
  IA, aucun autre champ n'est modifié.
* Marquer les résultats désactivé : le champ ajouté existe mais sans étiquette « produit par IA ».
* Vérifier que l'appel à l'agent ne consomme pas le budget en crédits (3.8.08) de la même façon
  qu'un appel de source payante — ce n'est pas le même système de facturation, à bien séparer dans
  le journal pour ne pas fausser le compteur budget.
