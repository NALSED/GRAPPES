# 1.2 — Réglages avant Recherche

Répond au point **1.2** du pavé de Sednal du 02/11/2026 : « Le bouton réglage doit être avant
Recherche. »

Modifie le document **04** de la série `suite/pilote/` dans `NALSED/GAPPES-FINAL`
(`04-onglets-et-navigation.md`).

## Ce qui change

Le nouvel ordre des quatre onglets, fixe comme l'ancien :

| Onglet | Pictogramme | État |
| :-- | :-- | :-- |
| Tableau de bord | `tableau-de-bord` | conçu (document `18`, voir spec `1.1`) |
| **Réglages** | `reglages` | conçu |
| **Recherche** | `recherche` | conçu |
| Tri | `tri` | conçu le 26/10/2026 |

Seul Réglages et Recherche s'échangent. Tableau de bord reste premier, Tri reste dernier.

**Et l'application s'ouvre désormais sur Réglages**, pas sur Recherche. Décidé par Sednal le
02/11/2026 : cohérent avec le fait que ce bouton passe en tête de la barre.

## Ce que momo change, concrètement

### `static/suite/js/mots.js`

Réordonner le tableau `ONGLETS` :

````js
export const ONGLETS = [
  { id: "tableau-de-bord", nom: "Tableau de bord", icone: "tableau-de-bord", concu: true },
  { id: "reglages", nom: "Réglages", icone: "reglages", concu: true },
  { id: "recherche", nom: "Recherche", icone: "recherche", concu: true },
  { id: "tri", nom: "Tri", icone: "tri", concu: true },
];
````

(`tableau-de-bord` passe à `concu: true` par la spec `1.1` — si celle-ci n'est pas encore
implémentée au moment de traiter ce point, laisser `concu: false` ici et ne changer que l'ordre de
Réglages et Recherche.)

La barre se construit en bouclant sur ce tableau (`main.js`, fonction `barre()`) : aucun autre
changement n'est nécessaire pour que l'ordre visuel suive.

### `static/suite/js/main.js`

Deux occurrences câblées en dur sur `"recherche"` comme page de départ :

````js
// avant
app.onglet = m ? m[1] : "recherche"; // Tableau de bord et Tri ne sont pas conçus : on n'y va pas

// après
app.onglet = m ? m[1] : "reglages";
````

Le commentaire disparaît : les deux onglets qu'il visait sont désormais conçus (Tableau de bord par
la spec `1.1`, Tri depuis le 26/10).

Vérifier qu'aucun autre endroit du fichier ne suppose `"recherche"` comme onglet de départ (recherche
du littéral `"recherche"` dans tout `main.js` avant de considérer le point clos).

### `suite/pilote/04-onglets-et-navigation.md` (GAPPES-FINAL)

Mettre à jour le tableau des quatre onglets dans le nouvel ordre, et ajouter une ligne sous le
tableau :

> L'application s'ouvre sur **Réglages**.

## Ce que ça ne change pas

* Les routes `#/recherche`, `#/reglages`, `#/tri`, etc. : les ancres ne changent pas, seul l'ordre
  d'affichage des boutons dans la barre change.
* Le contenu des pages elles-mêmes.
* Les sous-parties de Réglages (*Sources*, *Outils*) et de Recherche (*simple*, *avancée*,
  *sauvegardées*) : inchangées.

## Comment momo vérifie

* La barre affiche les boutons dans le nouvel ordre.
* Ouvrir l'application sans ancre dans l'URL (`/suite`) atterrit sur Réglages.
* Une ancre explicite (`/suite#/recherche`) continue d'atterrir sur Recherche : seul le défaut
  change, pas la navigation directe.
* Les tests existants (`test_suite_navigateur.py`) naviguent toujours avec une ancre explicite
  (`/suite#/recherche`, `/suite#/tri`), jamais sur `/suite` nu, et ne présument d'aucun ordre fixe des
  boutons — **aucun test existant à adapter**. Momo peut ajouter un test sur l'atterrissage par défaut
  (`/suite` nu → Réglages) s'il veut fixer ce comportement, mais ce n'est pas une régression à
  corriger : c'est un comportement nouveau.
